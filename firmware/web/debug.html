Checking update service…

Checks and recovery

The instrument checks the hardware/unit identity embedded in the application, package size and SHA-256 digest. It writes the inactive firmware slot and selects it only after complete image verification. A new boot must pass local startup checks before acceptance; otherwise rollback is attempted. This package is integrity-checked, not cryptographically signed.

Peer labels distinguish preparation, updating, overdue and reconnected. A missed notice is ordinary link loss. Collection still requires fresh corrections and the required GNSS quality. After an interrupted upload, reconnect and read the outcome before retrying.
